# 粉丝团灯牌自动赠送工具

给 B 站关注列表里正在直播中的主播各送 1 个粉丝团灯牌，当日去重不重送。
支持按粉丝牌等级过滤，默认仅向粉丝牌 15 级及以上的主播送礼。

## 快速开始

1. 安装依赖：`pip install -r requirements.txt`
2. 首次运行：`python main.py --dry-run`
   - 若没有 `.env`（或 cookie 失效），会自动弹出终端二维码，用哔哩哔哩 APP 扫码登录
   - 登录成功后 cookie 自动写入 `.env`，下次运行直接复用
3. 重新登录：`python main.py --login`（强制重新扫码，覆盖旧 cookie）
4. 预演（不花钱验证）：`python main.py --dry-run`
5. 正式运行：`python main.py`

## 参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--dry-run` | 只列出不实际送礼 | 关 |
| `--login` | 扫码登录重新获取 cookie（覆盖 .env） | 关 |
| `--min-interval` | 最小送礼间隔秒 | 0.5 |
| `--max-interval` | 最大送礼间隔秒 | 1.5 |
| `--min-medal-level` | 粉丝牌最低等级才送礼，设 0 关闭过滤 | 关注模式 15，分区模式 0 |
| `--only-no-medal` | 只给没有粉丝牌的主播送礼（与 --min-medal-level 互斥） | 关 |
| `--all-area [ID]` | 遍历指定父分区全部在播主播送礼（默认 ID=9 虚拟主播）。正式送礼前要求输入 yes 确认花费 | 关 |

## 登录说明

- 首次运行或 `.env` 缺失时自动触发扫码登录
- 终端打印 ASCII 二维码，用哔哩哔哩 APP 扫码并确认
- 登录成功后 cookie 存入 `.env`，后续运行自动复用，无需重复扫码
- cookie 失效时重新运行 `--login` 即可

## 本地记录

送礼结果存于 `sent_log.json`，按日期分组。当日已成功赠送的主播不会重送；
失败的主播当日可重试。跨天自动新建当日记录。

## 说明

- 默认送关注列表里 `live_status==1`（直播中）的主播，轮播跳过；分区模式走 web 端
  `second/getList` 接口（Wbi 签名 + w_webid 令牌），仅返回开播中的直播间，
  另有 0.5s/页节流与 -352 风控退避重试，可选逐房间复核开播状态
- `--all-area` 模式会翻页拉取整个父分区的在播主播（虚拟主播分区约数百个开播），
  **花费可能较大**：预计金额 = 灯牌单价 × 待送数，正式送礼前必须输入 `yes` 确认。
  建议先用 `--dry-run` 估算
- 粉丝牌等级通过 `fansMedal/panel` 接口翻页获取全部粉丝牌：
  `--min-medal-level N` 只送 ≥N 级的；`--only-no-medal` 只送没有粉丝牌的；
  两者互斥。分区模式默认不过滤，需要时显式传参
- 余额不足立即停止整轮
- 灯牌为付费礼物（gift_id=31164，100 金瓜子 = 0.1 元/个），请知悉
